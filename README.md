# healing-room-sync

용산힐링룸(`용산힐링룸 서울역10분`)의 **삼삼엠투(33m2)** 와 **직방** 두 채널을 10분마다 자동으로 맞춰 주는 프로그램입니다.
사람이 브라우저로 두 사이트를 번갈아 확인하지 않아도 되도록, 달력과 요금을 코드가 직접 읽고 필요한 것만 고칩니다.

```
삼삼엠투 room 93770  ↔  직방 item 2649
```

---

## 1. 무엇을 자동으로 하는가

| 항목 | 규칙 | 비고 |
| --- | --- | --- |
| **날짜(막기)** | 결제·계약이 잡힌 쪽을 기준으로 **반대쪽을 막는다** (양방향) | 막기만 자동 |
| **날짜(풀기)** | **자동으로 풀지 않는다.** 필요해 보이면 아무것도 바꾸지 않고 알림만 | 사람 확인 |
| **가격** | 주 요금(임대료) / 관리비 / 청소비를 **항목별 1:1** 로 맞춘다 | 직전 실행 대비 **최근에 바뀐 쪽**이 기준 |
| **판정 불가** | 같은 주기에 양쪽이 모두 바뀌면 아무것도 쓰지 않고 알림 | |
| **이상값** | 0원, 500만 원 초과, 반대쪽의 3배 초과는 적용하지 않고 알림 | |
| **실패** | 한 단계라도 실패하면 그 회차는 변경 없이 종료하고 알림 | 부분 변경 금지 |
| **정상** | 아무 알림도 남기지 않는다 | |

한 회차에 새로 막아야 할 날짜가 90일을 넘으면 자동 적용을 멈추고 알림만 남깁니다(오작동 방지).

## 2. 실행 방식과 비용

- **GitHub Actions, public 저장소** — 10분 간격(하루 144회, 월 약 4,320회)을 **무료**로 돌리기 위한 선택입니다.
  - private 저장소는 Free 플랜 2,000분/월인데 회당 최소 1분 과금이라 10분 주기(월 4,320회)는 한도를 넘습니다.
  - public 저장소는 Actions 실행 시간이 무제한이고, **Secrets 는 공개되지 않습니다**(로그에도 출력되지 않음).
  - 코드에는 자격증명이 전혀 들어가지 않습니다. 저장소 Settings → Secrets 에만 둡니다.
- 회당 실행 시간: 실측 **약 10~20초**(표준 라이브러리만 사용, 브라우저 없이 HTTP 요청만).
  - `pip install` 없음 → 실행 준비가 빠르고 깨질 요소가 적습니다.
- 실패·판정불가·해제필요 같은 예외만 **이 저장소의 Issue** 로 남깁니다(`힐링룸동기화` 라벨, 같은 내용은 24시간에 한 번만).
푸시·메일은 보내지 않습니다(원하면 `SMTP_USER`/`SMTP_PASS` 를 넣어 메일도 함께 받을 수 있습니다).
알림이 이슈로 기록되면 워크플로는 성공으로 끝냅니다 — 실패로 끝내면 GitHub 이 매 회차 실패 메일을 보내기 때문입니다.

## 3. 구조

```
sync.py                  실행기 (읽기 → 판정 → 적용 → 알림 → 상태 저장)
hrsync/m33.py            삼삼엠투 어댑터 (로그인·일정·요금 읽기/쓰기)
hrsync/zb.py             직방 어댑터 (로그인·일정·요금 읽기/쓰기)
hrsync/plan.py           판정 규칙 (순수 함수, 네트워크 없음)
hrsync/httpc.py          쿠키 자동 관리 HTTP 클라이언트
hrsync/notify.py         알림 (GitHub Issue, 선택: 메일)
hrsync/state.py          상태 파일 원자적 저장
tests/test_plan.py       판정 규칙 단위 테스트 20개
tools/smtp_sink_test.py  메일 경로 점검용(로컬 가짜 SMTP)
.github/workflows/sync.yml  10분 스케줄
state/state.json         직전 실행의 요금·달력 스냅샷 (커밋됨, 비밀 없음)
state/session.json       로그인 세션 (커밋 금지, Actions cache 로만 보관)
```

실행:

```bash
python3 sync.py --mode dry-run          # 읽기만, 비교 결과만 출력
python3 sync.py --mode apply            # 실제 반영
python3 -m unittest discover -s tests   # 규칙 테스트
```

---

> **스케줄은 기본 브랜치에서만 돕니다.** 이 저장소의 기본 브랜치는 `master` 이고, 코드도 `master`·`main` 양쪽에 같은 내용으로 들어 있습니다.
> `.github/workflows/sync.yml` 은 반드시 **`master`(기본 브랜치)** 에 두어야 10분 스케줄이 걸립니다.


## 4. 처음 설정 (Secrets)

저장소 → Settings → Secrets and variables → Actions → **New repository secret**

| 이름 | 값 | 필수 |
| --- | --- | --- |
| `M33_EMAIL` | 삼삼엠투 로그인 이메일 | ✅ |
| `M33_PASSWORD` | 삼삼엠투 비밀번호 | ✅ |
| `ZB_EMAIL` | 직방 로그인 이메일 | 직방 자동화에 필요 |
| `ZB_PASSWORD` | 직방 비밀번호 | 위와 동일 |
| `ZB_COOKIE` | 직방 세션 쿠키 문자열 (`이름=값; 이름=값`) | 비밀번호가 없을 때 대체 |
| `SMTP_USER` / `SMTP_PASS` / `ALERT_TO` | (선택) 이슈 대신 메일도 받고 싶을 때 | ❌ |

`ZB_EMAIL`/`ZB_PASSWORD`(또는 `ZB_COOKIE`)가 없으면 **직방 어댑터를 안전하게 건너뜁니다**: 로그에 `[직방] 건너뜀 — …` 이 남고, `[힐링룸동기화] 확인이 필요합니다` 이슈로 사유가 기록됩니다(24시간 중복 억제). 이때는 비교·자동수정을 하지 않습니다(양쪽을 다 읽어야 판정할 수 있으므로).

## 5. 로그인·세션 관리

### 삼삼엠투 — 사람 손 없이 계속 돕니다

웹 로그인 화면이 쓰는 서버 액션(`signIn`)에 이메일/비밀번호를 보내면 `__Secure-session-token` 쿠키가 발급됩니다.
쿠키 수명은 30일이고, 매 실행마다 새로 로그인하면 서버가 `COMN_003 / 처리중입니다`(409)로 잠깐 막는 일이 있어
**로그인 세션을 저장해 재사용**합니다(`state/session.json`, Actions cache 보관, 저장소에는 커밋하지 않음).
세션이 만료돼 401이 오면 자동으로 다시 로그인합니다.

> 비밀번호를 바꾸면 Secrets 의 `M33_PASSWORD` 만 바꾸면 됩니다. **1단계.**

### 직방 — 지금은 자격증명이 필요합니다

직방은 호스트 API(`stay-apis.zigbang.com/host/items/…`)가 로그인 세션 없이는 403 입니다.
로그인 방법은 두 가지이며 둘 다 어댑터에 구현돼 있습니다.

**(가) 이메일 + 비밀번호 (권장, 스스로 유지됨)**
직방 `POST https://account.zigbang.com/v2/user/token` 에 `{"email","password"}` 를 보내는 방식입니다.
현재 계정은 구글 로그인으로만 쓰이고 있어 비밀번호가 없으면, 직방에서 비밀번호를 한 번 만들어 두고
Secrets 의 `ZB_EMAIL`/`ZB_PASSWORD` 에 넣으면 이후로는 사람 손이 필요 없습니다.

**(나) 세션 쿠키 주입 (비밀번호를 만들지 않을 때)**
데스크톱 브라우저에서 직방에 로그인한 뒤 개발자도구(F12) → Application → Cookies → `zigbang.com` 에서
값을 복사해 `이름=값; 이름=값` 형태로 `ZB_COOKIE` 에 넣습니다.
갱신 절차는 **2단계**입니다.
1. 직방에 로그인한 브라우저의 쿠키를 위 방법으로 복사한다.
2. 저장소 Secrets 의 `ZB_COOKIE` 값을 바꿔 저장한다(다음 실행부터 적용).

> 쿠키는 만료되면 401/403 이 오고, 그때 "직방 세션이 만료됐습니다" 이슈가 열립니다. 그 이슈를 보고 위 2단계를 반복하면 됩니다.
> 참고: Pickle 쪽 브라우저에서는 보안 정책상 쿠키를 읽어 올 수 없어, 세션 추출은 **사람이 브라우저에서** 해야 합니다.

## 7. 안전장치

- 해제(차단 풀기) API 는 코드에 있지만 **동기화 경로에서는 호출하지 않습니다**(테스트가 소스로 검사).
- 직방 예약불가 저장은 "목록 전체 교체" 방식이라, 기존 차단에 새 날짜를 **더한 합집합**만 보냅니다.
- 사용자가 만든 차단·계약(2026-11-29~2027-01-19, 2027-02-02, 2027-01-26~02-01 등)은 지우지 않습니다.
- 결제·예약 생성·계약 취소 기능은 없습니다.
- 쓰기 후에는 **다시 읽어 확인**하고, 확인에 실패하면 알림을 남깁니다.
- 한 회차에 90일 초과로 막아야 하면 자동 적용을 멈춥니다.

## 9. 남은 위험

- **직방 자격증명**: 아직 없어서 직방 쪽 동기화는 돌지 않습니다. 위 5장 참고.
- **화면 개편**: 두 사이트 모두 비공식 경로(서버 액션 ID, 내부 REST)를 씁니다. 삼삼엠투는 액션 ID가 바뀌면 자동으로 다시 찾지만, 응답 구조가 바뀌면 읽기 실패 → 이슈가 열립니다.
- **로그인 제한**: 삼삼엠투가 짧은 간격의 반복 로그인을 409로 막는 경우가 있어 세션을 재사용합니다. 세션이 만료된 시점에 409가 겹치면 한 회차를 건너뛰고 알림을 남깁니다.
- **GitHub cron 지연**: 무료 스케줄은 수 분 늦게 뜰 수 있습니다(10분 간격 → 실제 10~20분).
- **직방 요금 항목 해석**: 직방은 관리비 미포함/청소비 포함 같은 플래그가 있어, 값이 없는 경우 `None` 으로 다룹니다. 실제 응답으로 한 번 더 확인이 필요합니다.
